# Сборка CapSync.exe (Windows)

Собирать нужно НА САМОЙ Windows-машине — PyInstaller не умеет кросс-компилировать
с Mac. Сам exe — тонкий лончер (аналог launch.command), всю тяжесть (faster-whisper,
модель) CapSync доставляет себе сам при первом запуске, через экран установки.

## Один раз на машине, где собираем

```bat
py -3.11 -m pip install --upgrade pip pyinstaller
```

(нужен Python 3.11/3.12 — на 3.14+ часто ещё нет готовых wheel-ов под ctranslate2/av)

## Сборка

Из корня папки `capsync/`:

```bat
py -3.11 -m PyInstaller --onefile --name CapSync --console launch_windows.py
```

Результат: `dist\CapSync.exe`. Положить его РЯДОМ с остальной папкой `capsync`
(venv создастся в `capsync\.venv`, run.py запустится оттуда же — лончер сам
находит свою папку через `sys.executable`, если собран как `--onefile`).

`--console` оставлен специально — на первом запуске видно, что именно качается/ставится,
и это единственное окно, которое сразу покажет ошибку, если что-то не так с Python
(до того как смог бы открыться сам webview). Можно поменять на `--windowed` позже,
когда всё стабилизируется и такой диагностический вывод перестанет быть нужен.

## Что проверить на реальной Windows после сборки (не проверено с Mac)

- Путь к папке CapCut (`core/osdetect.py`, `_candidates()` для Windows) — сейчас
  это образованная догадка (`%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft`),
  не подтверждённая на живой установке. Если не найдётся — экран настроек покажет
  инструкцию и поле для ручного пути, но сам путь-угадайку стоит сверить и поправить.
- `core/capcut_app.py` — закрытие/переоткрытие CapCut по имени процесса `CapCut.exe`
  (через psutil, кросс-платформенно, но не прогнано живьём на Windows).
- WebView2 Runtime должен быть на машине — на Windows 11 и большинстве актуальных
  Windows 10 он уже есть (ставится с Edge); если его нет, pywebview сам подскажет на
  старте.
